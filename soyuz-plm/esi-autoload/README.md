# Автозагрузка ЭСИ в Союз ПЛМ

Скрипт `AutoLoadEsi.cs` сам заполняет состав сборки из файлов, которые кладут
в папку входящих. Он повторяет логику команды «Сформировать состав на основе
Excel» из конфигурации «Создать сборку на основании Excel» (репозиторий
pidrpen/cursor, папка pmszcfg): тот же поиск исполнений по обозначению или
наименованию в контейнерах 436 и 9, та же коллекция `Items`, единица «шт»
и тип связи «конструкторская». Отличие одно: скрипт запускается по расписанию
на сервере, а не кнопкой.

## Файлы

- Имя файла: обозначение сборки, например `АБВГ.123456.001.csv`.
- Внутри: `Обозначение;Наименование;Количество`, UTF-8, разделитель `;`.
  Пример лежит в `example.csv`. Строка заголовка пропускается сама.
- Если обозначения нет, позиция ищется по наименованию (как в исходной команде).
- Позиции, которые уже есть в составе, второй раз не добавляются.
- После загрузки файл уходит в `Загружено` (или в `Ошибки`), а рядом с ним
  ложится `.log`, где по строкам видно, что добавлено, а что не найдено.

CSV, а не xlsx, потому что серверная задача работает без Excel. Из Excel
файл сохраняется через «Сохранить как → CSV UTF-8».

## Как подключить в Союзе

Готовый `.pmszcfg` отсюда собрать нельзя: это двоичный пакет, который пишет
сам Союз. Поэтому подключение делается в редакторе конфигураций:

1. Создайте конфигурацию «Автозагрузка ЭСИ».
2. В ней создайте элемент реестра `ZUMRoot\EsiAutoLoad\InboxFolder`
   (строка) с путём к папке входящих, доступной серверу Союза. Если его нет,
   берётся `C:\SoyuzEsiInbox`.
3. Создайте скриптовую функцию (серверную) с ключом `AutoLoadEsi` и вставьте
   код из `AutoLoadEsi.cs`. В usings конфигурации нужны `System.IO`,
   `System.Linq` и `System.Text`.
4. В свойствах функции включите повтор по расписанию (например, каждые
   15 минут) и сохраните конфигурацию.
5. Положите `example.csv` под именем существующей сборки в папку и
   дождитесь запуска, затем проверьте состав и `.log`.

Скрипт написан по коду ваших конфигураций и на живом Союзе не запускался.
