# Подпись выпусков и закреплённый пакет Tesseract

С 2026.10.21.2 CursorPad ставит обновление, только если `version.txt`
подписан ключом выпусков, и запускает Tesseract, только если пакет — ровно тот,
что закреплён в программе.

## Обновления

`version.txt` и `CursorPad.bin` приходят с одних и тех же зеркал (jsDelivr,
raw.githubusercontent.com, github.com, api.github.com). Отпечаток sha256 в
`version.txt` подтверждает только целостность: подменивший файл подменит и его.
Поэтому 4-я строка `version.txt` — подпись:

```
2026102102
2026.10.21.2
sha256 <отпечаток CursorPad.bin>
== 0 signature-rsa-sha256 <base64>
== 2026.10.21.2
…что нового…
```

Подписывается строка `CursorPad-update\n<номер>\n<версия>\n<sha256>\n`
(RSA-3072, PKCS#1 v1.5, SHA-256). Программа сверяет её открытым ключом из
`update_key.h` (CryptoAPI Windows). Нет подписи, она не сходится или нет
отпечатка — exe не скачивается и не ставится, в отчёте проверки об этом
сказано. Старые версии CursorPad видят строку подписи как заголовок «версии 0»
и не показывают её в «Что нового».

Подпись ставит `package_release.py` при каждой сборке (`build.ps1`,
`build.sh`). Без ключа сборка останавливается: выпуск без подписи всё равно
никто бы не поставил.

### Где ключ

Закрытый ключ **не хранится в репозитории** и не должен туда попасть.

| Откуда | Что |
| --- | --- |
| `CURSORPAD_UPDATE_KEY_PEM` | сам ключ (текст PEM) в переменной окружения — для облачной сборки (секрет среды) |
| `CURSORPAD_UPDATE_KEY` | путь к файлу ключа |
| по умолчанию | `%LOCALAPPDATA%\CursorPad-release\update-signing-key.pem` |

**Сделайте резервную копию файла ключа** (флешка, менеджер паролей). Если
ключ потерян, новые выпуски программа принимать не будет: её придётся один раз
поставить вручную со страницы выпуска на GitHub, а ключ — создать новый.

Сборка на другом ПК или в облачной среде: передайте туда ключ через
`CURSORPAD_UPDATE_KEY_PEM` (секрет) или файл. Без него выпуск там не соберётся.

### Новый ключ

```
python native/update_sign.py --make-key
```

Создаёт ключ (через `openssl`), если его ещё нет, и пишет `update_key.h`.
Плановая смена ключа: выпустите версию, подписанную **старым** ключом, но с
**новым** `update_key.h`; когда она разойдётся, подписывайте новым.
`package_release.py` проверяет, что `update_key.h` соответствует ключу,
которым подписывает, — иначе программа такой выпуск не приняла бы.

## Пакет Tesseract

Раньше пакет из общей папки `CursorPad-PLM\tesseract` сверялся с `pack.txt`
из той же папки: любой с правом записи туда мог подложить свой
`tesseract.exe`. Теперь отпечаток `pack.txt` закреплён в программе
(`tess_pack.h`), а отпечатки файлов берутся из него. Пакет из общей папки, с
зеркал или рядом с exe ставится и запускается, только если совпадает. Папку
пакета перед первым запуском в сеансе программа сверяет целиком; подменённый
файл — Tesseract не запускается, текст читает Windows OCR, а «Проверить
обновления» ставит пакет заново.

Новый пакет: `python native/make_tess_pack.py <папка tesseract>` — он
пишет и `tess_pack.h`; до ПК пакет дойдёт вместе с новой версией программы.
Только заголовок по готовому `public/tess/pack.txt`:
`python native/make_tess_pack.py --pin`. Сборка не пройдёт, если
`tess_pack.h` не от текущего `public/tess/pack.txt`.
