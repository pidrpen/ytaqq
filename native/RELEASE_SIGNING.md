# Подпись выпусков и закреплённый пакет Tesseract

## Обновления

С 2026.10.22.2 CursorPad подпись выпуска **не проверяет**. Выпуск собирается
без ключа где угодно, в том числе в облаке:

```
sh native/build.sh          # Linux / облако
powershell -File native/build.ps1
```

Скачанный `CursorPad.bin` сверяется с отпечатком sha256 из 3-й строки
`version.txt`; нет отпечатка или он не совпал — exe не ставится. Это защищает
от недокачанного и испорченного файла, но не от подмены: кто может записать в
`main` репозитория (или подменить зеркало), тот может выпустить своё
обновление, и оно встанет у всех. Права на запись в `pidrpen/ytaqq` — только
тем, кому это можно доверить.

### Старые версии

2026.10.21.2–2026.10.22.1 ставят обновление, только если `version.txt`
подписан ключом выпусков (открытый ключ вшит в них). Поэтому:

- 2026.10.22.2 подписан — все, у кого эти версии, переходят на него сами;
- `package_release.py` подписывает выпуск, если ключ есть на ПК, где идёт
  сборка; нет ключа — выпуск без подписи. На такой выпуск сами обновятся
  только версии 2026.10.22.2 и новее, а застрявшие на 2026.10.21.2–2026.10.22.1
  — со следующим выпуском, собранным с ключом, или вручную со страницы выпуска.

Подпись — 4-я строка `version.txt`, `== 0 signature-rsa-sha256 <base64>`
(RSA-3072, PKCS#1 v1.5, SHA-256 над `CursorPad-update\n<номер>\n<версия>\n<sha256>\n`).
Программа видит её как заголовок «версии 0» и не показывает в «Что нового».

Ключ (не в репозитории): `CURSORPAD_UPDATE_KEY_PEM` (текст PEM),
`CURSORPAD_UPDATE_KEY` (путь) или `%LOCALAPPDATA%\CursorPad-release\update-signing-key.pem`.
Когда старых версий не останется, файл ключа можно удалить.

### Вернуть обязательную подпись

Из истории git: `update_key.h`, `upd_sig_check` в `update.c` и
`update_sign.py --make-key` (коммит «CursorPad 2026.10.21.2»). Первый выпуск с
проверкой ставится без неё, проверять будут следующие.

## Пакет Tesseract

Раньше пакет из общей папки `CursorPad-PLM\tesseract` сверялся с `pack.txt`
из той же папки: любой с правом записи туда мог подложить свой
`tesseract.exe`. Теперь отпечаток `pack.txt` закреплён в программе
(`tess_pack.h`), а отпечатки файлов берутся из него. Пакет из общей папки, с
зеркал или рядом с exe ставится и запускается, только если совпадает. Папку
пакета перед первым запуском в сеансе программа сверяет целиком; подменённый
файл — Tesseract не запускается, текст читает Windows OCR, а «Проверить
обновления» ставит пакет заново.

Новый пакет: `python native/make_tess_pack.py <папка tesseract>` — он
пишет и `tess_pack.h`; до ПК пакет дойдёт вместе с новой версией программы.
Только заголовок по готовому `public/tess/pack.txt`:
`python native/make_tess_pack.py --pin`. Сборка не пройдёт, если
`tess_pack.h` не от текущего `public/tess/pack.txt`.
