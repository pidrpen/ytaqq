# Подпись выпусков и закреплённый пакет Tesseract

CursorPad ставит обновление, только если `version.txt` подписан ключом
выпусков (с 2026.10.21.2; исключение — 2026.10.22.2, где проверка снималась,
с 2026.10.22.3 она снова обязательна), и запускает Tesseract, только если
пакет — ровно тот, что закреплён в программе.

## Обновления

`version.txt` и `CursorPad.bin` приходят с одних и тех же зеркал (jsDelivr,
raw.githubusercontent.com, github.com, api.github.com). Отпечаток sha256 в
`version.txt` подтверждает только целостность: подменивший файл подменит и его.
Поэтому 4-я строка `version.txt` — подпись:

```
2026102203
2026.10.22.3
sha256 <отпечаток CursorPad.bin>
== 0 signature-rsa-sha256 <base64>
== 2026.10.22.3
…что нового…
```

Подписывается строка `CursorPad-update\n<номер>\n<версия>\n<sha256>\n`
(RSA-3072, PKCS#1 v1.5, SHA-256). Программа сверяет её открытым ключом из
`update_key.h` (CryptoAPI Windows). Нет подписи, она не сходится или нет
отпечатка — exe не скачивается и не ставится, в отчёте проверки об этом
сказано. Программа видит строку подписи как заголовок «версии 0» и не
показывает её в «Что нового».

## Как выпустить

### Из облака — GitHub, с одобрением владельца (основной путь)

1. Куратор поднимает номер в `native/version.h` и `native/version.txt`,
   пишет абзац в `native/whatsnew.txt` и сливает это в `main`.
2. Срабатывает `.github/workflows/build-release.yml` («Сборка выпуска»):
   собирает exe на Windows тем же компилятором, что на ПК (WinLibs GCC 16.2.0
   r1, отпечаток архива закреплён), без ключа.
3. Задание «publish» ждёт одобрения: GitHub присылает письмо, кнопка —
   Actions → запуск → **Review deployments → release → Approve** (можно из
   приложения GitHub на телефоне).
4. После одобрения `version.txt` подписывается (`update_sign.py --sign`),
   проверяется (`--verify`), `public/` уходит в `main`, выпуск — на страницу
   релизов. Тогда его получают все.

Если сборка не нужна (выпуск уже пришёл с ПК вместе с `public/`), запуск
ничего не делает. Не одобрили — ничего не выходит; отклонить — **Reject**.

**Перед «Approve»** посмотрите, что вошло с прошлого выпуска (ссылка на
коммит в запуске). Особенно — менялся ли `.github/`: правка сборки может
вытащить ключ, и одобрение такого запуска его отдаст.

### С ПК

```
powershell -File native/build.ps1
```

Ключ на ПК — выпуск подписывается сразу. Затем `public/` в `main`:
`release.yml` проверит подпись и выложит релиз. Без ключа `version.txt`
выходит неподписанным; `release.yml` такой не выложит, а программа не
поставит.

## Где ключ

Закрытый ключ **не хранится в репозитории** и не должен туда попасть.

| Откуда | Что |
| --- | --- |
| GitHub → Settings → Environments → `release` | секрет `CURSORPAD_UPDATE_KEY_PEM` — для «Сборки выпуска»; виден только шагу подписи и только после одобрения |
| `%LOCALAPPDATA%\CursorPad-release\update-signing-key.pem` | ПК владельца |
| `CURSORPAD_UPDATE_KEY_PEM` / `CURSORPAD_UPDATE_KEY` | текст ключа / путь к нему в переменной окружения |

Положить ключ в GitHub (один раз, с ПК владельца):

```
gh secret set CURSORPAD_UPDATE_KEY_PEM --env release --repo pidrpen/ytaqq < "$LOCALAPPDATA/CursorPad-release/update-signing-key.pem"
```

Одобрять может только `pidrpen` (окружение `release`, только ветка `main`).
Облачным исполнителям ключ не передаётся, и личный токен GitHub владельца у
них быть не должен: с ним можно одобрить запуск самому.

**Сделайте резервную копию файла ключа** (флешка, менеджер паролей). Если
ключ потерян, новые выпуски программа принимать не будет: её придётся один раз
поставить вручную со страницы выпуска на GitHub, а ключ — создать новый.

### Новый ключ

```
python native/update_sign.py --make-key
```

Создаёт ключ (через `openssl`), если его ещё нет, и пишет `update_key.h`.
Плановая смена ключа: выпустите версию, подписанную **старым** ключом, но с
**новым** `update_key.h`; когда она разойдётся, подписывайте новым и замените
секрет в окружении `release`. `update_sign.py` проверяет, что `update_key.h`
соответствует ключу, которым подписывает, — иначе программа такой выпуск не
приняла бы.

## Пакет Tesseract

Раньше пакет из общей папки `CursorPad-PLM\tesseract` сверялся с `pack.txt`
из той же папки: любой с правом записи туда мог подложить свой
`tesseract.exe`. Теперь отпечаток `pack.txt` закреплён в программе
(`tess_pack.h`), а отпечатки файлов берутся из него. Пакет из общей папки, с
зеркал или рядом с exe ставится и запускается, только если совпадает. Папку
пакета перед первым запуском в сеансе программа сверяет целиком; подменённый
файл — Tesseract не запускается, текст читает Windows OCR, а «Проверить
обновления» ставит пакет заново.

Новый пакет: `python native/make_tess_pack.py <папка tesseract>` — он
пишет и `tess_pack.h`; до ПК пакет дойдёт вместе с новой версией программы.
Только заголовок по готовому `public/tess/pack.txt`:
`python native/make_tess_pack.py --pin`. Сборка не пройдёт, если
`tess_pack.h` не от текущего `public/tess/pack.txt`.
