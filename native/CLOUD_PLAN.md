# План для облачного проекта: куратор + Haiku 5.5 → CursorPad

Репозиторий: `pidrpen/ytaqq`, ветка `main` (версия 2026.10.21.1). Код — `native/`,
сборка под Linux: `native/build.sh` (MinGW). Реальные чертежи и рабочие файлы
в облако НЕ передаются.

## Роли
- **Куратор** (сильная модель): раздаёт задачи, проверяет код и данные,
  сливает ветки, ведёт этот план.
- **Haiku 5.5 ×N**: каждый — одна задача в своей ветке `cloud/<задача>`,
  результат — PR с описанием, собранный exe и пройденные тесты.

## Правила для всех
- Одна задача — одна ветка, файлы задач не пересекаются (список ниже).
- `-Wall -Werror` без предупреждений; существующие тесты (`chat_format_test`,
  `agent_files_test`, `word_format_test`, `office_test`) проходят.
- Новый инструмент агента = код инструмента + описание в схеме
  (`ai_agent_schema.h` / `make_agent_schema.py`) + тесты + строка в `AI_TOOLS.md`.
- Изменения файлов только через план «было → станет» и кнопку «Применить».
- Версию, `public/` и выпуск не трогать — это делает куратор/человек.

## Задачи данных для дообучения 4B (без секретов)
Формат: JSONL, `{"messages":[...]}` в шаблоне чата Qwen; ответы-планы —
строго по схеме инструментов CursorPad.
- **D1 router**: 1500 реплик «болтовня / файловая задача / поиск / уточнить»,
  разговорный русский, опечатки («ексель», «ворд»).
- **D2 tools**: 2000 просьб → правильный JSON-вызов инструмента (Word, Excel,
  папки, сравнение, отчёт).
- **D3 formulas**: 1000 описаний → формула Excel (RU-имена функций), каждая
  проверена вычислением.
- **D4 persona**: 500 коротких живых диалогов в стиле помощника.
- **D5 tp**: ТП по учебным/открытым деталям (вал, втулка, фланец, кронштейн)
  — формат и логика ТП; куратор проверяет каждую.
- Куратор: дедупликация, проверка JSON по схеме, отбраковка, отложенная
  проверочная выборка 10 %.
